# Mori 集中式 Agent 布局

2026-11-12，按用户要求将工程 Agent 配置收拢到一个 `.harness/` 目录，以根目录 AGENTS.md 为唯一入口正文，CLAUDE.md 使用指向它的相对软链。此前的原生目录布局见[历史重建记录](mori-clean-reinitialization.md)，本轮结果见[结构化记录](mori-centralized-layout.json)。

```text
AGENTS.md
CLAUDE.md -> AGENTS.md
.harness/
  docs/        中文工程指南
  skills/      共享工作流说明
  commands/    按名称访问的操作流程
  agents/      委派任务说明
  rules/       工程与证据约束
  resources/   环境自检和隔离烟测脚本
  state/       历史任务与追加日志
  runtime/     独立检查器
  ...          生成输入、来源记录和工作区登记
```

原 .codex、.claude、.agents 目录和外置工程 Skill 已移除；工程指南移至 .harness/docs。根目录的任务清单、日志、初始化脚本和旧标记也已收拢或归档。现有任务 CLI 适配新的状态路径，同时兼容旧仓库的任务文件位置；相关 README 和历史资料中的当前指南链接已更新。

这次集中的是工程 harness。应用、产品设计资料和其他正常仓库目录保留。全部原有 89 个任务对象和追加日志前缀保持一致；旧布局和本轮完整证据保存在仓库外的私有备份目录。

## Kit 支持

新增 `centralized` 与 `native` 布局选择，保存在初始化资料和生成输入中。集中布局约束文档与资源输出位置，生成真实入口软链，并校验类型、目标、冲突和刷新一致性；普通写入失败会回滚软链与文件。旧配置未指定布局时保留原生行为，新初始化 Skill 优先选择集中布局。

集中布局通过 AGENTS.md 路由共享流程，不注册宿主原生 Skills、斜杠命令或子代理。设置、hook 与 CI 需要显式选择 native 布局。检查与 doctor 的宿主验收说明也随布局调整，不能将旧原生目录的发现记录继续算作本轮生效证据。
