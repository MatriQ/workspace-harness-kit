# Synthetic task handoff request

Use the explicitly synthetic repositories materialized by `examples/materialize.py`
as the original material for this fixture. Their roles are caller/request producer,
shared-state writer, asynchronous consumer, verifier and policy source. The concrete
repository count and fake claim domain make this case reproducible; they are not
default Harness requirements and must not be copied into an unrelated project's
guidance. Keep their existing documents in place. Initialize a centralized Harness
documentation hub with Simplified Chinese project prose, Codex and Claude Code,
development, testing, local startup and bounded local investigation. Reuse tools;
do not log into a provider, deploy, enroll another repository or alter member files.
Disposable local verification is allowed. Record local paths, actual ports and run
state only in ignored `*.local.md` and required ignored runtime evidence files.

Prepare enough source-backed guidance for a reader to answer these tasks:

1. A license-state/schema change is proposed. Which selected components read/write
   the relevant data, what contract must be checked on both sides, and where are
   the implementation and regression entry points?
2. Health is green but a claim is refused. How can the reader distinguish a disabled
   claim from the wrong signature contract without treating health as acceptance?
3. The request was accepted but the license remains pending. Which regional
   producer/consumer observations distinguish acceptance from final completion?
   What retry/idempotency behavior is actually supported by the fixture?
4. A handbook describes a single regional worker in 2024. Which current source
   supports or conflicts with that statement, and what online conclusion remains
   unknown?
5. Does the local fixture prove a hosted broker or an unexamined downstream works?
   What evidence or authorization would be needed before making that claim?

Author replay starts from the final Agent entry point and follows the generated
routes. Record missing mappings and revise/replay affected tasks. An independent
reader, when authorized, gets this request, generated docs and allowed original
materials, without reviewer notes or an author's answer/score report. They record
answers with sources, extra source searches, interventions, execution and gaps.
Shared structure checks, task knowledge, actual behavior, host activation and hosted
delivery remain separate. No fixed file/word/scenario quota is part of the assessment.
