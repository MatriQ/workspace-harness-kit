# Mori 本地 Skill 耗时演练

本报告记录 2026-11-12 在本地 Mori 仓库及相同源码版本的隔离副本上进行的测量。原检出目录保持干净：453 个受跟踪文件的哈希、Git 状态和 HEAD 均未改变。生成的指南、任务记录与构建输出均保留在副本中。详见[结构化结果](mori-latency.json)。

后续[初始化与验证实际演练](mori-functional-rehearsal.md)补充了原生测试、候选服务构建、隔离启动和生成指南重放。它们不属于下述耗时测量。

## Agent 工作流观测

| 工作流 | 实测总耗时 | 其中的子进程执行 |
| --- | ---: | ---: |
| 独立 harness-init 编写者 | 460.940 秒 | 13 次 Kit helper 调用合计 0.909 秒 |
| 新读者的 harness-guide 路由阶段 | 127.541 秒 | 读取源码，未调用子 helper |
| 随后的 harness-test 阶段 | 140.966 秒 | 两个测试入口合计 2.724 秒 |

指南与测试工作流总计 354.091 秒，包含阶段切换与最终报告。每个工作流均只有 **1 个样本**，不能解释为 Agent 延迟百分位数。计时从首次记录的操作开始，到结果保存结束，不包含初始派发。总耗时包含读取、推理、工具往返、等待和报告。未测量纯模型推理耗时、token 或费用。

编写者增加了一份工程索引和 AGENTS 受管入口，复用现有指南覆盖 4 个选定主题，并保留 86 个历史任务对象。它审阅了 32 个显式生成来源和 46 个登记来源；7 份文档审阅、严格工作区检查和生成文件检查均通过。新读者正确区分了原生 Swift 启动与 Node/Python 开发工具，并识别出启动包装脚本可能选用已安装运行时，而不是候选检出目录中的版本。

## 正确性、失败恢复与限制

- 每次纳入测量的测试均通过全部 8 个用例，无失败或跳过。独立 Web 工作流还通过了 39 个 JavaScript 文件和 10 个 Python 文件的语法检查。
- 副本起初缺少 Prettier 和 Ruff，快速验证在 Prettier 处停止，失败记录已保留。通过临时链接复用原检出目录中已安装的工具后，单独重试在 1.902 秒内通过。随后移除临时链接；没有安装依赖，也没有修改原源码。
- npm 预检曾因配置路径设置错误失败，改用不同的本地空配置路径后恢复，两次尝试均被保留。
- 一个额外的严格检查批次与格式工具重试重叠。该批次被保留，但未计入表格；表中严格检查数据来自后续串行重测。
- 默认来源清单不会自动识别 SwiftPM manifest，编写者显式登记了 Swift manifest 和实现来源。有界命令解析器仍将直接 Swift 测试命令标为待检查；这一阶段的文档未声称它已执行。
- 本耗时阶段未执行原生构建或测试、应用启动、宿主自动加载、真实提供商或账号操作、云端部署。它验证的是本地文档、helper 和 Web 工具，不是原生启动延迟或网络延迟。

## 根据本次观测提出的优化方向

初始化 helper 的实测耗时约占工作流总耗时的 0.20%。应优先研究如何在保留来源审阅的前提下减少重复读取与报告：使用生成的任务索引，只展示必要的登记字段，将完整计划保存在本地，并汇总相关变更。可复用的源码事实与每次执行证据分开维护，有助于常规刷新关注变化。这些建议来自单次 Agent 运行，尚未经过对照验证。

确定性工具层继续使用现有捆绑 Node 方案，在提出性能改动前将上述阶段作为基线。Mori 暴露出的具体覆盖缺口是 SwiftPM 来源发现和 Swift 命令检查，应与速度问题分别评估。用户未指定延迟阈值，本次也未建立跨主机或跨模型 SLA。

原始执行记录、源码路径、生成文档和可运行测量脚本保留在私有本地演练目录。结构化摘要发布耗时、结果数量、Skill 摘要和证据文件哈希，不包含未经筛选的诊断或个人检出路径。本文的中文修订仅翻译说明，未重新测量或改变历史数据。
