## 运行时观测与失败恢复

烟测调用 Mori 自带的 `--init-local`，使用真实选定的检出目录和可用回环端口，创建全新的私有运行时目录，并验证了：

- 私有凭据权限及健康的原生服务元数据。
- 所属 PID、解析后的候选程序路径及二进制 SHA-256，未仅依赖多个构建共用的 `0.3.0` 版本号。
- HTML 与构建后的 `dist/web/index.html` 一致；源码清单和 Git 元数据请求返回 404。
- 新账号的登录门槛、本地运行设置，以及选定检出目录已由 worker 同步进临时数据库。
- 未提交模型任务，且结束后完成所属进程与运行时目录的清理。

首次烟测错误地预期仅持有本地 owner token 就能从 `/api/state` 获取项目。源码审阅确认该路由还要求登录真实 Mori 账号。失败记录被保留，相关进程也已清理。修订后的指南预期该接口返回 HTTP 401 和未登录状态，再通过受支持的 API 检查本地设置。对临时数据库的只读查询单独证明 worker 同步；它**不能证明**已登录用户的工作区验收已经通过。

修正后的烟测通过，随后直接重放最终生成指南也再次通过。整个过程没有伪造账号记录，也没有关闭认证检查。

## 证据边界

实际演练完成时，doctor 将选定的原生工具链和本地烟测记为通过，并绑定当时的生成配置、本地目标及候选哈希。整体结果仍为 **pending**，因为没有观测 Codex 宿主的真实发现与信任状态。这些是附有留存证据的执行确认，不能自动证明宿主已加载配置。

有界静态命令检查器仍将 4 处声明保留为待检查：两份文档中的 Swift 测试、Swift 构建和 Python heredoc。这些命令已通过源码审阅并实际执行，但静态解析器尚不支持它们。生成文件检查通过不能掩盖此项限制。

需要账号的业务行为，以及模型和提供商访问，仍需合适的测试账号验证。托管 CI、GUI 操作和云端发布验收未执行。工程任务检查器仍报告一项历史任务缺少验证命令的警告，本次没有改写该历史记录。

私有证据保留了首次失败烟测、修正后的烟测、指南原样重放、测试与构建日志、生成计划、审阅记录、doctor 观测和最终保护检查。共享 JSON 仅保存经筛选的结果与证据哈希。生成的 Mori 文档留在隔离副本中，未安装到原仓库。功能演练阶段未修改 Kit 核心或捆绑运行时。
